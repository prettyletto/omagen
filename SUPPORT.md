# Support

## Before opening an issue

Check the user documentation for [usage](docs/usage.md), [Demo](docs/demo.md),
and [recovery](docs/recovery.md). For development or branch questions, read
[`docs/development.md`](docs/development.md) and the [release process](docs/development/release-process.md).

## Where to ask

- Use GitHub Discussions for questions, ideas, and configuration help.
- Use a bug report for reproducible product problems.
- Use the compatibility form for Omarchy, Quickshell, Hyprland, or terminal
  integration differences.
- Use the crash/recovery form when Apply, Cancel, Quit, or restoration fails.
- Use private security reporting for suspected unsafe or malicious behavior.

Include the Omagen version, Omarchy/Quickshell/Hyprland versions, relevant
logs, reproduction steps, and whether the issue occurred during Preview,
Demo, Apply, Cancel, Quit, or Recovery. Remove paths, usernames, credentials,
and personal images before posting.

## Compatibility matrix

The maintainer has confirmed the current development branch works on both
supported Omarchy versions below. The promotion record should still attach
the exact test date, checkout SHA, and any live-desktop notes available.

| Omarchy | Status for v2.0.0 | Notes |
| --- | --- | --- |
| `4.0.2-1` | Maintainer-confirmed | Record Quickshell, Hyprland, kernel, and test date. |
| `4.0.1-1` | Maintainer-confirmed | Record upgrade and recovery results. |

During the first 30 days after release, maintainers will triage issues weekly.
Use the labels `crash`, `recovery`, `compatibility`, `packaging`, `security`,
and `UX` so reports can be grouped without collecting telemetry.
