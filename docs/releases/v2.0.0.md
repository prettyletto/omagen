# Omagen v2.0.0 release notes

This release records the exact stable `main` snapshot promoted through
`nightly → dev → main`. Marketplace verification remains a separate exact-
commit maintainer handoff.

## What is included

- Image-derived theme generation with six palette directions.
- Reversible Live Canvas Preview and staged Test Live flows.
- Temporary Demo workspaces with capability detection and fallbacks.
- Apply, Cancel, Quit, interrupted-session recovery, and rollback paths.
- Optional Window, Shell, Bar, Animation, and terminal composition.
- Two separately owned Omarchy packages: `pretty.omagen` and
  `pretty.omagen.bar`.
- Deterministic bundled Go backend and checked-in shader artifacts.

## Trust boundary and capabilities

Omagen is unsandboxed plugin code. It can read selected images and Omarchy
configuration, write generated themes and Omagen-owned session state, invoke
the bundled backend and explicitly reviewed user-level adapters, and interact
with the current Omarchy/Hyprland session. The installer installs user-level
plugin files and does not require `sudo`, package installation, or privileged
service setup.

The full capability inventory and security expectations are documented in
[`SECURITY.md`](../../SECURITY.md), [`NOTICE.md`](../../NOTICE.md), and the
[marketplace release process](../development/release-process.md).

## Mutable installation limitation

Marketplace verification is evidence for one exact source snapshot. An
installation from a mutable branch or an unpinned upstream URL may differ from
the verified commit and is not covered by that evidence. Testers should clone,
inspect, and install a full 40-character commit SHA using
[`scripts/install-branch.sh`](../../scripts/install-branch.sh).

## Upgrade, rollback, and uninstall

Before upgrading, allow an active Omagen session to finish or use its Restore
path. The backend session record is authoritative for recovery. Cancel, Quit,
and an interrupted next launch preserve user-owned themes, shell settings,
backgrounds, unrelated plugins, and resources without Omagen ownership markers.

To remove the development checkout installation, run:

```zsh
./uninstall.sh
```

The uninstaller recovers an active session first. Package-only removal through
the native plugin manager leaves Omagen state and permanent themes in place;
see the stable `main` README for the user-facing removal choice.
